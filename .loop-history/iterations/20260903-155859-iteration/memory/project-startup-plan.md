## 产品形态

- 面向类型：智能外呼统一中台的 B 端运营配置原型。
- 载体形态：可浏览的静态 HTML/CSS/JavaScript 演示原型及配套说明、标注。
- 主要使用角色：总部超管、租户运营和外呼任务查看人员。

## 项目目的

- 实现目的：纠正大众通信 SaaS 不提供定时重呼任务 ID 的事实，删除中台中不可填写、不可获取的关联任务 ID 功能。
- 评审对象：产品经理、研发、测试和大众通信对接人员。
- 需要验证的业务假设：删除关联任务 ID 后，仍可依靠计划重呼次数和人工确认记录完成配置门禁与最后一次计划呼叫判断。
- 不属于本次验证目标：不新增大众接口、不改变定时重呼与任务重呼方案、不重新定义计划重呼次数口径。

## 项目范围

- 本期模块：系统管理-业务场景、外呼场景-任务详情、功能说明和页面标注。
- 本期页面：`sys-scene` 大众通信配置区域、`scene-list` 大众通信重呼追溯区域、说明文档页面。
- 本期能力：移除关联任务 ID 输入、Mock 属性、保存必填校验、任务详情行、说明文字和标注字段；同步调整人工确认文案为只确认计划重呼次数与后台实际配置一致。
- 核心流程：选择需要重呼 → 选择定时重呼 → 填写计划重呼次数 → 确认已在大众后台完成定时重呼配置 → 保存 → 任务详情查看轮次与末次判断。

## 非本期范围

- 不做模块：除大众通信重呼外的系统管理、统计、计费和外呼结果模块。
- 不做页面：其他供应商配置页、其他平台任务详情和新页面。
- 不做能力：不提供定时重呼任务 ID 替代字段，不模拟不存在的接口，不删除计划重呼次数，不删除人工确认，不改变任务重呼风险确认。

- 是否沿用底座设计：是，只收缩表单和详情字段，不重做布局。
- 参考风格：用户截图中的现有定时重呼人工配置卡片，红框表示需删除的字段区域。

## 整体页面结构

- 导航结构：保持现有系统管理与外呼场景导航不变。
- 页面列表：业务场景配置、外呼任务详情、功能说明文档、交互说明文档。
- 页面跳转关系：系统管理 → 业务场景 → 编辑大众通信场景；外呼场景 → 外呼列表 → 查看大众任务 → 任务详情。
- 页面职责：配置页负责保存方式、次数和人工确认；详情页负责只读追溯次数、确认记录、当前/最大轮次及末次判断。

## 核心流程

- 用户入口：编辑大众通信业务场景。
- 主流程步骤：开启重呼，选择定时重呼，填写计划重呼次数，完成后台配置后勾选人工确认并保存；之后在大众任务详情中查看配置追溯和末次结论。
- 关键状态：不重呼、定时重呼未确认、定时重呼已确认、任务重呼已知悉风险、非最后一次计划呼叫、最后一次计划呼叫。
- 异常或空状态：计划重呼次数为空、非整数或小于 1 时阻止保存；未人工确认时阻止定时重呼保存；不再出现关联任务 ID 为空错误。

## 验收方向

- 本轮完成后应看到：截图红框中的“关联重呼任务 ID”整行消失，相关提示和确认文案不再提及任务 ID。
- 必须可用页面：大众业务场景编辑、三条大众任务详情、Markdown/HTML 功能说明、交互说明。
- 必须跑通流程：定时重呼只凭计划次数和人工确认保存；次数变化使确认失效；详情末次公式仍正确；任务重呼分支保持正常。
- 标注策略：用户要求同步修改标注；先在 S9 生成提示词，再回写本轮完整标注并验证 marker。

## 约束和风险

- 技术约束：静态原型无真实接口；不得留下已删除字段的 JS 读取、Mock 属性或保存校验。
- 资料风险：用户口述事实优先于上一轮“存在关联任务 ID”的假设。
- 字段风险：删除字段后必须重排 FLD 编号或完整更新锚点字段合同、标注 fieldRefs 和逐字段说明，避免残留引用。
- 人工核对项：人工确认只表示操作人已完成大众后台配置且计划重呼次数一致，不表示接口校验成功。
