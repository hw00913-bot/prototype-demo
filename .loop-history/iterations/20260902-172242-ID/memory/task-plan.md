# 任务计划

## 项目目标

- 在不改动其他平台逻辑的前提下，将大众通信重呼从“只有说明提示”升级为可选重呼方式、人工确认门禁和可追溯详情。
- 使用“计划重呼次数（不含首次）”计算最大呼叫轮次，支持最后一次计划呼叫的可观察判断。
- 同步更新完整功能说明、交互说明、字段追溯、验收证据和本轮标注。

## 阶段计划

1. 扩展大众场景和任务详情 Mock，建立重呼方式、确认记录与呼叫轮次数据。
2. 改造业务场景中的大众配置面板，完成不重呼/定时重呼/任务重呼分支、必填校验和确认失效逻辑。
3. 改造外呼列表大众任务详情，只读展示重呼方式、人工确认信息、当前/最大呼叫轮次和末次判断。
4. 同步功能说明与交互说明，完成全局回归、本轮标注提示词、标注回写和终态复验。

## 当前优先级

- P0：定时重呼关联任务 ID、计划重呼次数和人工已配置确认必须形成保存门禁。
- P0：任务重呼必须明确告知已完成任务不再触发待重呼的风险，并要求知情确认。
- P0：计划重呼次数不含首次，末次判断公式在页面、说明、验收和标注中一致。
- P1：人工确认人与时间可追溯，关键字段变更后自动失效。

## 风险与依赖

- 大众平台未提供定时重呼配置或查询接口；中台只能记录人工声明，页面不得冒充系统校验。
- 底座是无构建步骤的 ES5 页面代码，修改必须保持原有写法与全局 Mock 分离。
- 非大众平台属于回归范围而非修改范围，任何其他平台表单或详情变化都视为回归失败。
