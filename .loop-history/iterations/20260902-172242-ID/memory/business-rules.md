# 已确认业务规则

## 业务对象定义

- **主任务**：中台通过 UUID 关联的大众通信外呼任务。
- **定时重呼关联任务**：由操作人在大众后台人工配置的重呼承接任务；中台只记录任务 ID。
- **人工确认记录**：操作人对外部平台已完成配置或已知悉风险的声明，包含确认状态、确认人和确认时间。
- **呼叫轮次**：同一号码的首次呼叫记为第 1 次，后续每次重呼依次加一。

## 关键字段含义

- “计划重呼次数”不包含首次呼叫；填写 2 表示最多为 1 次首呼 + 2 次重呼 = 3 次计划呼叫。
- 最大呼叫轮次 = 计划重呼次数 + 1。
- 当前呼叫轮次大于等于最大呼叫轮次时，“是否最后一次计划呼叫”为是。
- 客户已接通、明确拒绝或其他不再满足重呼条件时，可提前结束该号码流程；这一结果与“最后一次计划呼叫”的次数判断分开。

## 主要状态和枚举

- 是否需要重呼：不需要 / 需要。
- 重呼方式：定时重呼 / 任务重呼。定时重呼为默认且推荐选项。
- 定时重呼配置状态：尚未人工确认 / 已人工确认。
- 任务重呼风险状态：尚未知悉 / 已知悉。
- 计划呼叫位置：非最后一次 / 最后一次计划呼叫。

## 交互与保存规则

- 选择“不需要重呼”时，隐藏重呼方式和所有确认字段，可正常保存。
- 选择“需要重呼”时，默认为“定时重呼”。
- 定时重呼必须填写关联重呼任务 ID、大于等于 1 的整数计划重呼次数，并勾选“已在大众后台完成定时重呼关联配置”，否则阻止保存。
- 任务重呼必须勾选“已知悉任务无待呼号码后会完成，后续待重呼号码可能不再触发”，否则阻止保存。
- 定时重呼的人工确认成功时，记录当前演示用户和浏览器当前时间。
- 修改主任务 UUID、关联重呼任务 ID、计划重呼次数或重呼方式后，原有确认状态、确认人和确认时间必须清空。

## 权限或角色边界

- 原型不新增角色权限矩阵，沿用底座对业务场景的管理权限。
- 能够新建或编辑业务场景的操作人可录入人工确认；任务详情对具备底座查看权限的用户只读展示。
- 人工确认不代表大众平台已经返回验证结果。

## 异常、空状态或边界规则

- 大众主任务 UUID 缺失时不得保存。
- 定时重呼关联任务 ID 为空、计划重呼次数不是大于等于 1 的整数或未确认平台配置时，就地提示并阻止保存。
- 任务重呼未勾选风险知情时，就地提示并阻止保存。
- 详情字段缺失时显示“-”；未人工确认时显示“尚未人工确认”，不得显示为系统校验失败。
- 原型不设置平台未确认的重呼次数硬上限。
