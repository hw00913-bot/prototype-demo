## 决策详情

### DEC-001: 整合多个接入方原型到统一项目

- **决策时间**：2026-08-19
- **决策内容**：将demo_AI_call目录下的10个原型项目整合到当前项目
- **决策依据**：用户希望展示智能外呼平台的完整能力，作为产品介绍或销售演示
- **影响范围**：项目结构需要重新组织，数据需要整合，功能需要合并
- **备选方案**：保持各原型独立、选择部分原型整合
- **最终选择**：全部整合

- **影响范围**：样式文件、组件设计、交互方式
- **备选方案**：统一分格、采用特定规范
- **最终选择**：保留当前风格

### DEC-006: 完整版说明 Markdown 作为唯一内容源

- **决策时间**：2026-08-21
- **决策内容**：仅维护 `docs/功能说明文档.md` 的业务内容；`docs/功能说明文档.html` 由 `tools/render_doc_html.py` 生成，不保留额外兼容 HTML。
- **决策依据**：用户坚持保留完整版说明作为唯一事实，并要求 HTML、Markdown 同步，减少重复维护。
- **影响范围**：完整版说明、交付导航、项目级 Loop/S9 门禁和文档校验流程。
- **维护方式**：修改 Markdown 后运行 `python3 tools/render_doc_html.py`；提交前运行 `python3 tools/render_doc_html.py --check`。
- **最终选择**：Markdown 唯一内容源 + 唯一生成 HTML；交付导航与项目级 Loop 门禁均直接引用完整版 HTML。

### DEC-007: 统一权限章节作为角色权限唯一维护出处

- **决策时间**：2026-08-24
- **决策内容**：在 `docs/功能说明文档.md` 的“五. 其他说明”中维护唯一角色权限表；各功能章节、项目业务规则及页面标注仅引用该章节，不重复权限全文。
- **决策依据**：用户要求降低权限变更时的同步范围和后续维护成本。
- **影响范围**：完整版说明文档、`memory/business-rules.md`、标注提示词、标注覆盖说明和 55 条正式标注。
- **维护方式**：角色、数据范围或模块权限变化时只修改统一权限章节并重新生成 HTML；标注中的 `permissionScope` 保持固定出处引用。
- **最终选择**：权限口径单一出处 + 其他位置只引用。
