# 任务计划

> 本计划面向“充值功能迭代”的 S7 实现与单步验证。每项实施必须以当前项目记忆、字段映射和真实文件结构为准。

## 项目目标

在现有智能外呼中台静态原型内，完成标准版年包、话费充值包、统一分钟池、内部充值流水、手工调增/调减、租户商用/试用标记和当前租户两级使用明细；保留原有冻结/消耗闭环，不恢复新充值的外部单号依赖。

## 实施范围

- 管理端：租户标记、租户充值管理、套餐/充值包表单、内部记录、手工调整。
- 租户端：右上角使用情况入口、按日明细、任务级二级明细。
- 数据：租户、权益、统一分钟池、内部充值/调整记录、按日和任务用量。
- 兼容：原有冻结、释放、结算；历史外部单号和金额记录只读兼容；历史记录抽屉缺陷最小修复。
- 交付：本地 HTML 业务流程图、时序交互图、关联系统明确空态。

## 阶段计划

当前评审修正：STEP-11 完成五项页面反馈；STEP-12 按 SRC-013 复用需求分析原图，并增加试用租户独立使用套餐（0 元/30 天/500 分钟，可编辑）。这两步覆盖下列首次实现描述中的旧范围。

1. STEP-01 建立统一分钟池与内部记录 mock 基线。
2. STEP-02 在租户列表和编辑中维护商用/试用标记及账户概览。
3. STEP-03 重构租户充值管理的信息架构和内部记录。
4. STEP-04 实现标准版与话费充值包表单、校验和生效预览。
5. STEP-05 实现使用时长/可用分钟的手工调增与调减。
6. STEP-06 新增右上角使用情况入口和按日明细。
7. STEP-07 新增每日任务分钟消耗二级明细。
8. STEP-08 验证并修复冻结/释放与历史记录兼容。
9. STEP-09 生成本地 HTML 业务流程图。
10. STEP-10 生成本地 HTML 时序交互图并确认关联系统空态。

## 依赖关系

- STEP-01 是所有业务页面的数据前置。
- STEP-02 为管理端租户上下文和标记提供入口。
- STEP-03 为 STEP-04、STEP-05 和 STEP-08 提供充值管理容器。
- STEP-06 为 STEP-07 提供当前租户和选中日期。
- STEP-09、STEP-10 在业务页面和兼容验证完成后生成。

## 风险与处理

- OI-001：不实现未到期续费叠加。
- OI-002：历史外部单号只读保留，新记录不使用。
- OI-003：50% 话术边界不自动判定。
- OI-004：历史金额调整不折算。
- OI-005：若历史租户抽屉错误复现，只做阻断演示的最小修复。
- 导航技术债：现有导航由 index 与 js/nav.js 共同维护，config/nav.json 只含首页；本轮修改需三者一致且避免无关导航重构。
