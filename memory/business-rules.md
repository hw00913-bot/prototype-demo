## 任务状态枚举

任务状态及六个平台原始值映射的唯一维护出处为：`docs/功能说明文档.md` → “五. 其他说明 → 1. 外呼任务统一状态与六平台映射”。

- 中台固定使用 13 项 `TaskExecuteStatus`（code 1–12、14，无 code 13）。
- 页面展示和筛选必须使用映射后的中台 code；平台原始值单独保留。
- 未知平台值显示“未映射”，禁止回退“未启动”。
- 电声 `statusType` 与批次字段 `executeStatus` 不得混用。

## 通话状态枚举

25 项 DCC 通话状态、全平台归并规则和厚朴 770–790 映射的唯一维护出处为：`docs/功能说明文档.md` → “五. 其他说明 → 2. DCC 通话状态与全平台映射”。

- 列表、筛选、详情、线索和报表使用同一 DCC 状态。
- 一知、科大、中科金、电声、大众通信和厚朴按统一主表映射；冰兰保留 `callStatus` 与 `missedCallReason` 原始值，缺少权威映射的原因不得擅自归并。
- 厚朴必须同时保留 `rawStatusCode`、`rawStatusName` 与映射后的 DCC 状态。
- 已确认口径：779 呼出限制→呼叫受限；782 呼叫转移→无法接通；790 摘机后未识别状态→无人接听。
- 厚朴 `770`–`790` 的完整 DCC 归并表是本项目确认的中台本地业务映射，列表、筛选、报表和对账以该表为准；原始码与原始描述仍必须保留。

## 厚朴 OpenAPI v2 接入边界

- OAuth2 凭据、访问令牌、真实回调地址及来源校验只允许存在于中台服务端，不进入浏览器、Mock、日志或标注。
- 厚朴任务必须预先在厚朴平台创建；中台不再调用任务创建接口，只接收已有 `task_id` 并通过服务端任务查询能力校验后保存关联关系。
- 原型使用模拟的服务端默认厚朴账号查询任务；开发实现时从受控服务端配置取得默认账号，不允许前端传入凭据。
- 同一厚朴 `task_id` 全局只允许关联一个业务场景；编辑当前场景时可保留原关联，关联到其他场景的 ID 必须拦截并提示已关联场景。
- 打开厚朴任务详情、打开已关联场景的编辑页，或主动点击“查询并关联”时，必须通过服务端任务查询接口重新读取任务状态，不使用上次保存的状态快照代替实时状态。
- 任务查询成功即可关联，原型不按 `0`–`6` 的具体任务状态限制关联；页面同时展示厚朴原始状态和中台映射状态。
- 任务名称、机器人、号码模板、任务类型、执行时段、并发、重呼和未呼优先均来自任务查询结果，在中台只读展示，不作为可编辑的创建参数。
- 任务 ID 为空、查询不到任务、默认账号不可用、任务 ID 已关联其他场景，或任务 ID 变更后未重新查询时，禁止保存业务场景。
- 号码导入使用 `outnum`：Excel/CSV/TXT，首行为表头、首列号码、后续列为模板动态属性；建议单批不少于 200，单文件最多 150,000 个号码，每任务最多 50,000 批。
- 导入结果以平台返回的 `batch_id` 与有效号码数为准；回调按任务、批次和呼叫标识幂等去重。

## 报表整合规则

- 通话统计、计费统计和线索记录必须显式保留智能平台字段，并支持六个平台的展示或筛选。
- 大众通信线索保留 A-F 意向等级及“未评级”状态；电声线索保留平台专属意向文案和多次回访明细。
- 计费统计按租户、智能平台和计费类型共同展示，不以同名租户覆盖不同平台记录。

## 异常/空状态规则

- 数据为空时显示"暂无数据"
- 加载中显示"加载中..."
- 查询无结果显示"未找到匹配数据"
- 网络错误显示"请求失败，请稍后重试"
