## 产品形态

- 面向类型：企业内部 SaaS 管理后台演示原型。
- 载体形态：静态 HTML/CSS/JavaScript 多页面原型。
- 主要使用角色：外呼运营人员、任务查看人员、产品评审人员。

## 项目目的

- 实现目的：精简大众通信任务详情的重呼追溯信息，只保留用户当前需要查看的配置摘要。
- 评审对象：大众通信重呼方案的产品与业务评审人员。
- 需要验证的业务假设：任务详情无需展示人工确认明细、当前呼叫轮次及末次判断，保留重呼方式、计划重呼次数和人工配置确认状态即可满足查看需求。
- 不属于本次验证目标：不调整场景配置页的人工确认门禁，不改变任务实际调度与呼叫逻辑。

## 项目范围

- 本期模块：大众通信任务详情重呼追溯区。
- 本期页面：外呼列表中的任务详情弹窗；与该展示直接相关的说明文档和标注。
- 本期能力：删除“确认记录”“当前呼叫轮次”“是否最后一次计划呼叫”三项展示及详情页专用计算。
- 核心流程：进入外呼列表，打开大众通信任务详情，查看精简后的重呼追溯区。

## 非本期范围

- 不做模块：其他供应商外呼、报表、标签、租户、线索与通话结果模块。
- 不做页面：不改场景配置页面的字段布局和保存流程。
- 不做能力：不删除计划重呼次数，不删除人工配置确认状态，不新增接口或替代字段，不变更真实后台业务。

## UI 风格

- 视觉基调：沿用现有后台表格、分区标题与只读详情样式。
- 是否沿用底座设计：是。
- 参考风格：用户截图中现有“大众通信重呼追溯”区块。
- 禁用风格：不新增卡片、图表、提示弹窗或额外装饰。

## 整体页面结构

- 导航结构：沿用现有主导航与“外呼列表”入口。
- 页面列表：外呼列表任务详情、功能说明、交互说明、标注层。
- 页面跳转关系：外呼列表 → 查看大众任务 → 任务详情。
- 页面职责：详情页只读展示重呼方式、计划重呼次数和人工配置确认状态。

## 核心流程

- 用户入口：外呼列表中的“查看”操作。
- 主流程步骤：打开大众通信任务详情 → 定位“大众通信重呼追溯” → 查看三项保留信息。
- 关键状态：定时重呼展示人工配置确认；任务重呼展示风险知情状态，维持既有分支。
- 异常或空状态：配置数据缺失时使用现有横线或未配置状态，不恢复被删除字段。

## 验收方向

- 本轮完成后应看到：红框内三行内容完全消失，区块在“人工配置确认”后结束。
- 必须可用页面：大众通信任务详情；配置页回归不受影响。
- 必须跑通流程：打开定时重呼与任务重呼示例任务，均无被删除内容；页面无控制台错误。
- 标注策略：同步更新现有人工标注，删除对确认记录、轮次和末次判断的说明。

## 约束和风险

- 技术约束：保持静态原型现有结构，不引入新依赖。
- 资料风险：截图仅标出详情页内容，按页面范围理解，不扩展为删除配置记录数据。
- 字段风险：确认人/时间及当前轮次 Mock 可能被其他逻辑使用，本轮不做无依据的数据层清理。
- 人工核对项：核对红框三项均不再渲染，说明与标注不存在旧口径。
