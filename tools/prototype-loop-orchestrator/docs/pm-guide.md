# PM 使用指南

本文面向产品经理，说明如何发起、确认和评审一个原型 loop。本文不定义执行门禁，执行以 `orchestrator/` 和项目内 `tools/loop_run.py` 为准。

## 发起方式

当需要把需求生成可评审原型时，输入“开始计划项目”，并尽量提供：

- 产品目标
- 目标用户
- 页面范围
- 非本期范围
- 核心流程
- 关键数据对象
- 参考项目、截图、FLOWCHART 流程图、API 文档或历史项目
- 迭代方式：新建项目或基于现有项目迭代
- 标注策略：自动生成、手动触发或本轮不处理
- 验收标准
- 交付方式

如果只输入“开始计划项目”，Agent 必须先追问这些内容，不能直接进入项目拆分或实现。

## 必须确认的内容

进入实现前，必须确认：

- 产品目标
- 目标用户
- 范围和非范围
- 输入材料
- 迭代方式
- 标注策略
- 核心页面
- 核心流程
- 主要数据对象
- 验收标准
- 交付目标

确认结果必须先写入项目启动规划。PM 明确确认后，总控在 S2 记录本轮名称、确认人和当前会话确认依据，并把启动规划和 CLAUDE.md 的内容摘要绑定到审批记录；文件之后发生变化会要求重新确认。只存在文件或由完成命令自动生成时间戳不算 PM 确认。

S2 确认后，Agent 需要写入项目级 `CLAUDE.md`；S3 再把启动规划转换为 `memory/project.md`、`memory/business-rules.md`、`memory/source-materials.md`、`memory/field-map.md` 和 `memory/open-items.md`。这些机器状态和记忆文件由脚本和 Agent 维护，PM 不需要手动编辑。

## 评审产物

交付时应能看到：

- 可打开的静态原型
- 页面标注
- 交互说明
- 流程图集
- 已知限制
- 验证摘要

生成项目顶部固定提供三个交付视图：

- 原型页面：进入业务原型和业务导航。
- 说明文档：展示交互、状态、数据来源、验收规则和已知限制。
- 流程图集：左侧选择流程，右侧展示 ProcessOn 流程图。

这三个入口独立于业务侧栏，并在当前页面内通过统一内容区切换，不发生整页跳转；URL 的 `#delivery=` 会保留当前选中视图。即使项目基于底座迭代或重写业务导航，也必须保留该入口。

说明文档直接加载 docs/interaction.html，不再额外维护一个重复的 docs/index.html 中间页。

说明文档统一采用“功能说明文档”格式：版本说明、项目范围、逻辑说明、功能说明、其他说明五章。功能说明按页面或完整业务功能拆分，每节包含功能名称、交互说明、数据来源、逻辑说明和七列功能明细表。文档使用白底表格型版式和蓝色标题/按钮，不生成 Hero、卡片看板或营销式概览页。

## 维护流程图集

生成项目内固定包含 `flowcharts/` 目录。产品经理只需要把 ProcessOn 链接逐行粘贴到 `flowcharts/processon-links.txt`，刷新 `flowcharts/index.html` 后，页面会自动在左侧生成分组目录，并在右侧嵌入选中的流程图。

推荐每行使用：`分类 | 流程名称 | ProcessOn 嵌入链接`。也可以写成 `流程名称 | 链接`，或只粘贴链接。流程图内容仍在 ProcessOn 维护，loop 不复制、不改写外部流程图。

旧项目缺少统一交付视图或 `flowcharts/` 时，由 Agent 在 loop 源仓库执行 `create_project.py 目标项目路径 --sync-flowcharts`。该操作会补齐内部切换壳和流程图集，保留已经填写的链接，并只给自定义业务首页与说明文档追加统一导航脚本，不改写业务侧栏或说明文档正文。

继续修改已有原型项目前，总控会先从当前安装技能执行 `create_project.py 目标项目路径 --sync-runtime`。它只刷新项目内 loop 脚本、阶段技能和三视图内部切换壳，保留业务页面、项目记忆、标注、说明文档正文和 ProcessOn 链接。这样旧项目不会继续使用上一次生成时携带的过期规则。

## 查看当前状态

产品经理不需要理解脚本细节。每次运行 loop 后，可以查看：

- `memory/loop-status.md`

该文件会用人话说明：

- 当前阶段是什么
- 是否可以继续
- 阻塞原因
- 需要 PM 确认什么
- 需要 Agent 补齐什么
- 下一步建议

内部执行文件如 `execution-steps.md`、`acceptance-map.md`、`workflow.json` 主要服务于系统追踪，不应成为 PM 的主要操作界面。

项目完成后若继续下一轮，总控使用 begin-iteration 先归档上一轮状态并回到 S0。PM 手工生成并回写标注后，总控使用 approve-annotations 重新验证；回写后未复验时，项目会显示终态已漂移。

## 交付（loop 外手工）

loop 在 S9 收尾终检通过后结束。把原型推送到 GitHub 是 **loop 外的手工步骤**——loop 不自动建仓或推送。本地 `git` 初始化、提交后推到预先创建的远端仓库即可。

## 边界

本 loop 生成演示原型，不承诺直接生成生产系统。真实后端、数据库、认证、安全合规、部署和生产级 QA 应作为后续工程化事项记录。
